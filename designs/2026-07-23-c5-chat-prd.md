# C5 — Chat PRD

## 1. Summary
C5 is the per-agent conversation surface: it renders one agent's thread, sends optimistically, assembles the streaming reply from `chat` deltas, dedups the gateway's echo of our own send by idempotency key, backfills history from `chat.history`, and shows a live activity indicator driven by real gateway signals only. It is a separate team because it is the app's highest-churn UI (bubbles, input bar, streaming, STT, file-down viewing) and it can be built and tested end-to-end against a mock `SyncSource` and golden JSON without any other feature's source. Its only outward coupling is the `ChatView(agent:)` entry point every other chunk consumes; everything it needs flows in through C0 types and the C1 `SyncSource` protocol, so it never reaches sideways into a sibling.

## 2. Scope
**In scope**
- `ChatView` — the per-agent thread screen (header + scroll of bubbles + input bar + activity line).
- `ChatViewModel` — optimistic send, streaming reply assembly, echo dedup by `clientMessageId`, history backfill, `activity` binding.
- Routing a thread to one agent via canonical session key `agent:<id>:main` and filtering the shared inbound stream with `InboundEnvelope.matchesAgent` (C1-owned, consumed here).
- Message rendering: `MessageBubble` (user green-tinted right, agent dark left, monospaced code, streaming caret, failed + retry).
- Live activity indicator UI bound to `AgentActivity` (label or nothing — never a fabricated verb).
- Client-side STT capture (`SFSpeechRecognizer` + `AVAudioSession`) that fills `draft`; no server round-trip.
- File-**DOWN** only: view / copy / share an artifact the agent already surfaced in-thread (`ShareLink`, `UIPasteboard`). Read-side, no upload.

**Out of scope**
- Roster, agent create/edit/delete, profile — **C6 (Agents/Roster)**. C5 receives an `AgentSummary`, never lists or mutates agents.
- The WebSocket, handshake, reconnect, `subscribe`/`loadHistory`/`send` wire calls, `InboundEnvelope` decode, `sessionKey` construction — **C1 (Transport)** behind the `SyncSource` protocol.
- Pairing, device token, scopes — **C2 (Auth)**.
- Theme tokens, `MonoField`, `PrimaryButton`, `ActivityLine` — **C3 (Design System)**.
- Conversation JSON persistence / settings store — **C4 (Local Store)**.
- Activity verb *mapping* (`AgentActivity.from(event)`) and the gateway daemons that emit those events — the enum lives in C0/C1; new event shapes are **C9 (Gateway)**.
- File **UP** (attaching/uploading from phone) — not in this product cut.

## 3. Interface (the stable contract)
**Exposes**
```swift
// The single public entry point. Every other chunk that shows a chat calls this.
struct ChatView: View {
    init(agent: AgentSummary, sync: any SyncSource, settings: SettingsStore)
}
```
`ChatViewModel` is `internal` — an implementation detail of C5, not part of the boundary. No other chunk imports it.

**Consumes (only via C0 or declared protocols)**
- C0 models: `ChatMessage`, `AgentSummary`, `AgentActivity` (+ `AgentActivity.from`), `GatewayError`.
- C1 protocol: `SyncSource` — `loadHistory(agentId:)`, `subscribe(agentId:)`, `activityStream(agentId:)`, and a **send entry** (`send(agentId:text:idempotencyKey:)`) that MUST be promoted onto the `SyncSource` protocol (today `ChatViewModel` down-casts `sync as? GatewayWSSyncSource` at line 136 — a boundary leak; see risks). Also consumes `InboundEnvelope.matchesAgent` for stream filtering.
- C3: `Theme` tokens, `MessageBubble` styling primitives, `ActivityLine`, `MonoField`, `PrimaryButton`.
- C4: `SettingsStore` (read-only: `isConfigured`, `model`).

## 4. Dependencies
Allowed: **C0** (models/contract), **C1** (`SyncSource` protocol only), **C3** (Design System), **C4** (Local Store). Nothing else.

Module-import rule (C10-enforced): C5 is a module `Chat` whose Package/target dependency list is exactly `[Contract, Transport, DesignSystem, LocalStore]`. `Agents` (C6), `Settings` (C7), `Surfaces` (C8), and `Gateway` (C9) are **not** listed, so `import Agents` from any C5 file is an unresolved-module **compile error**. The `SyncSource` protocol and `InboundEnvelope` are re-exported from C1; the concrete `GatewayWSSyncSource` must not be referenced by name (the current down-cast is the one violation to remove — once send is on the protocol, C5 needs no concrete type).

## 5. Milestones / build order
1. **Static thread** — `ChatView` + `MessageBubble` + input bar renders a passed-in `[ChatMessage]` against a mock `SyncSource`. Optimistic append on send; failed + retry state. (Largely exists.)
2. **Live pipeline** — `loadHistory` backfill (oldest-first insert), `subscribe` fan-in with `matchesAgent` filtering, streaming assembly from `chat` deltas, echo dedup by `clientMessageId`. Promote `send` onto `SyncSource`, delete the down-cast. (Largely exists minus the protocol promotion.)
3. **Activity indicator** — bind `activityStream` → `activity` → `ActivityLine`; render `label` or nothing.
4. **STT** — mic button fills `draft` via `SFSpeechRecognizer`; permission prompts + graceful denial. (Unbuilt.)
5. **File-down** — view/copy/share an in-thread artifact via `ShareLink`/`UIPasteboard`. (Unbuilt.)

## 6. Acceptance criteria
- Given golden `chat.history` JSON, `loadHistory` yields oldest-first messages inserted above the live thread; keys are registered so those turns never re-render on echo.
- Given a golden `chat` delta sequence, the assistant bubble fills incrementally and clears `isStreaming` on `final`; `aborted`/`error` mark it failed.
- Send appends the user bubble immediately with a `clientMessageId`; the gateway's echo carrying that same key is dropped (no double render) — asserted against a captured self-echo frame.
- An inbound event whose `agentId` differs from the thread's agent is filtered out (`matchesAgent` false); a bare session key without `agentId` is rejected — pinned to live-captured frames.
- `activityStream` events map to `AgentActivity` and the header shows the exact `label`; an unknown signal shows "Working…", never a fabricated verb (reuse `AgentActivityTests` fixtures).
- Demo mode (no host configured) renders and streams a canned reply — `DemoSyncSource` path preserved.
- STT: denied permission leaves `draft` untouched and surfaces no crash; granted dictation appends recognized text to `draft`.

## 7. Isolation proof
An agent in a fresh worktree can build C5 against the C0 models and a hand-written mock conforming to `SyncSource` (the protocol already fully specifies roster-free history/subscribe/activity/send), plus C3 styling primitives and a stub `SettingsStore` from C4. All seven acceptance tests run against golden JSON and an in-memory mock — no socket, no gateway, no C6 roster. The only thing C5 renders is a thread for one `AgentSummary` handed in at `init`; it never enumerates or mutates agents, so it has zero call into a sibling. The single existing coupling that breaks this (the `GatewayWSSyncSource` down-cast) is scheduled for removal in Milestone 2, after which C5's compile closure is exactly `{Contract, Transport, DesignSystem, LocalStore}`.

## 8. Status & risks
**Live/partial:** Milestones 1–3 are essentially built and live-verified (`ChatView.swift`, `ChatViewModel.swift`, `MessageBubble.swift`, `ChatInputBar.swift`, `AgentActivity.swift`, `AgentActivityTests.swift`); optimistic send, streaming, dedup, history backfill, and activity all work against the real gateway.

**Unbuilt:** STT (Milestone 4) and file-down view/copy/share (Milestone 5) — no `SFSpeech`/`ShareLink` code exists yet (grep confirms).

**Risks / open questions:**
- **Boundary leak (must fix):** `ChatViewModel` line 136 casts `sync as? GatewayWSSyncSource` to reach `send`. This names a C1 concrete type from C5 and silently no-ops for any other conformer. Promote `send(agentId:text:idempotencyKey:)` onto `SyncSource` (C0/C1 contract change) and delete the cast — otherwise C10's import rule can't be honored.
- **Subscription is single-shot:** on stream failure the thread does not auto-retry (ChatViewModel line 106). Decide whether reconnect/resubscribe is C1's job (auto-resubscribe on the shared connection) or C5 must re-arm — likely C1, to keep C5 dumb.
- **STT locale/permission** — default to device locale; on-device vs server recognition and the `NSSpeechRecognitionUsageDescription`/`NSMicrophoneUsageDescription` Info.plist entries need owner sign-off.
- **File-down source** — depends on the artifact/path shape C9 emits in a message; that DTO must land in C0 before Milestone 5 can start.
